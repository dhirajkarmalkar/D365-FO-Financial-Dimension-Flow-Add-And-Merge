1 · Dimensions
Three backing categories. The backing type sets where a dimension's values come from — a custom list you type, operating units (business unit, cost center, department, value stream) from Org admin, or an entity table (customers, vendors, workers, items, projects, fixed assets, banks, sites). Every dimension defaults onto transactions through the default financial dimensions on masters (set below), copies header→line, and fills blanks from the line source. Entity-backed dimensions additionally auto-populate as their own party account where that party is on the document — but, being ordinary dimensions, they can also be defaulted from any other master (a customer dimension carried on a vendor, item, project, and so on).
2 · Master-level vs line-level defaults
Master level = the default financial dimensions carried by the document's primary / header master — the customer, vendor, worker, project, fixed asset, bank, or journal name. They apply first, at the header, then copy to the line. Line level = defaults applied at the transaction line: the released product (item) and the site-linked dimension. They fill only the segments the master left blank — they never overwrite a value the master already set. Every dimension is a column here (entity-backed ones included), so you can, for example, set a customer dimension to default from a vendor or an item. Set a value once and every process reuses it wherever that source appears.
The Item row is the released product's default financial dimensions — the single value reused on every sales line, purchase line, inventory, production, and project-item transaction where the item is present. (In inventory and production the item is the primary master, so its value shows there as a header source.)
3 · Account structure
In D365 there's no "balance sheet vs P&L" switch on a dimension — the account structure decides it. For each main-account range, mark each dimension Required, Optional (allowed, blanks OK), or Not allowed (must be blank). At posting, the account's main-account range selects the row and any dimension not allowed there is stripped from that line — this is how, e.g., cost center posts on revenue but is blocked on receivables.
